NaOS v0.1.0

The first frozen release: a bootable, usable system. Own UEFI bootloader and kernel, shell, files, multitasking, USB keyboard, networking and three storage drivers — zero prebuilt OS code, MIT licensed.

Highlights

34 plain-English commands

Files, system, network, power — with history, output redirect and a themeable prompt.

AHCI · NVMe · ATA + FAT32

One block layer, writable FAT32, long filenames. Boots from SATA or NVMe.

fork() with CoW

Ring-3 programs, private address spaces, preemptive scheduler, copy-on-write fork, file syscalls.

TCP/IP + DHCP

E1000 driver, ARP/ping, UDP sockets, DHCP lease at boot, TCP client with HTTP fetch.

PS/2 + USB HID

Polled XHCI stack with hotplug rescan, classic PS/2 fallback, PC-speaker beeps.

ISO export

El Torito UEFI image via make iso, Rufus/DD-mode guide for real hardware.

Run it

Inside this folder. One-time host setup is in the README. No toolchain? Download NaOS.iso (CD boot) or NaOS.img (raw disk: attach as a VM hard disk for files, or dd to USB) — boot UEFI, Secure Boot off.

export PATH=/opt/cross/bin:$PATH
./tools/check.sh   # verify tools + OVMF
make all && make esp
make run           # → NaOS> shell
make run-iso       # needs xorriso: boot the ISO itself

Honest limits: TCP client only (no listen/DNS yet) · NVMe needs 512B namespaces · CD/USB boot is a live RAM session (files work, writes vanish on reboot; give the VM ≥256MB) · UEFI-only, Secure Boot off · writing files on real hardware writes the USB stick — back it up first.

How v0.1.0 was built

Boot + shell — custom BOOTX64.EFI, GOP console, NaOS> prompt
Memory — own PML4 paging, PMM, kmalloc heap
Files — ATA → AHCI DMA → writable FAT32 + long names
Multitasking — ring-3 tasks, syscalls, fork() with copy-on-write
Hardware — PCI scan, XHCI USB keyboard, PC speaker, ACPI power
Network — E1000, ARP/ping, UDP/DHCP, TCP client + HTTP fetch
NVMe — polled driver in the block layer; boots from NVMe
