What it does

Every line below the firmware is ours — bootloader, kernel, drivers, filesystem, scheduler, network stack.

Own UEFI bootloader

Custom BOOTX64.EFI in C: GOP framebuffer, ELF64 parsing, one-shot ExitBootServices, clean handoff to the kernel.

Plain-English shell

A NaOS> prompt with 30+ commands, history, output redirect and a themeable prompt via SETTINGS.TXT.

Real storage

AHCI, NVMe and ATA drivers under one block layer, with a writable FAT32 filesystem and long-filename reads.

Multitasking + fork

Ring-3 tasks with private address spaces, preemptive scheduler, syscalls, and copy-on-write fork(). Disk-loaded ELF programs.

TCP/IP networking

E1000 driver with ARP, ICMP ping, UDP sockets, a DHCP client and a TCP client — fetch pages over HTTP.

USB HID keyboard

Polled XHCI stack with hotplug rescan, next to the classic PS/2 driver. PC-speaker beeps included.

Speak to it

No Unix-isms. Type what you mean at the NaOS> prompt.

Build it

Windows + MSYS2 UCRT64, QEMU, and the /opt/cross toolchain. Full setup in the version README.

# inside versions/v0.1.0
export PATH=/opt/cross/bin:$PATH
./tools/check.sh  # verify every tool + OVMF
make all           # BOOTX64.EFI + KERNEL.ELF
make esp           # 64M FAT ESP image
make run           # QEMU + OVMF → NaOS> shell

  No build? Grab NaOS.iso from the release, boot it with Rufus (DD mode, Secure Boot off) — or browse the code online.
